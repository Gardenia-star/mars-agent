## 1. ⚠️ 最重要的一步：先激活 conda 环境

本机（`/ExtHDD/Users/yu/mars-agent`）的 Python 依赖装在 conda 环境 **`yu`** 里。
PyQt5 需要 `$CONDA_PREFIX/lib` 下的 `libGL / libGLX / libX11 / libgthread / libdbus` 等运行时库，
**只有激活环境后 `LD_LIBRARY_PATH` 才会指向它们**，否则会报：

```
ImportError: libgthread-2.0.so.0: cannot open shared object file
```

所以任何启动命令前面都要加：

```bash
source /ExtHDD/Apps/Anaconda/etc/profile.d/conda.sh
conda activate yu
```

> 已为该环境添加 `etc/conda/activate.d/zz_ld_library_path.sh`，
> 激活时会自动把 `$CONDA_PREFIX/lib` 加到 `LD_LIBRARY_PATH`（退出时自动还原）。
> 如果嫌每次都要 source，可在 `~/.bashrc` 里加一行：
> `source /ExtHDD/Apps/Anaconda/etc/profile.d/conda.sh && conda activate yu`

  Streamlit 会给自己的 `<img>` 加内联样式与多层包裹，外部 CSS 常常抢不过它，
  导致画面显示得很小；自己拼 img 尺寸才完全可控（帧会先限宽到 1280 再编码，约 13~32 KB）

### 2.2 操作流程（不同页面按钮不同）

| 页面 | 控制条 | 说明 |
|---|---|---|
| 性能监控 | **只有「上传」** | **载入视频/图片即自动执行分析**，无需再点按钮 |
| 过程诊断 | 上传 + **`🤖 AI 诊断`** | 载入同样自动分析；再点 AI 诊断生成大模型专家报告 |
| 加药分析 | 只有「上传」 | 载入自动分析后，建议由结果规则推算 |
| 历史管理 / 系统设置 | 只有「上传」 | 也能看到当前载入的源，随时可换 |

1. 在上方控制条的「📁 载入视频 / 图片」里选择火眼 **图片或视频**
2. 载入后**自动开始分析**
   - **图片**：即时判定（跳过时序迟滞，单张也能出结果）
   - **视频**：均匀采样（默认 24 帧，可在「系统设置」改），逐帧推理后给出趋势与报警
3. （过程诊断页）点 **`🤖 AI 诊断`** 让通义千问生成专家报告
4. 结果自动写入历史（含推算加药建议），可到「历史管理」筛选 / 查看详情 / 导出

> **载入一次，全程复用**：源文件与分析结果都存在 `session_state` 里（不是组件状态），
> 切到任何页面都不会丢，**不需要重新载入**。控制条在所有页面都渲染，
> 右侧会显示 `已载入 xxx.mp4（跨页面保留，无需重新载入）`。
>
> 视频画面固定在各页**左栏**：性能监控 / 过程诊断用全尺寸；加药分析用 0.5 倍尺寸的预览
> （控制条 + 左侧视频 + 右侧分析面板共用一屏，避免版面过高）。

### 3.2 本机没有显示器时（本机就属于这种）→ 浏览器远程桌面

```bash
cd /ExtHDD/Users/yu/mars-agent/Code
bash 启动远程桌面.sh
```

然后浏览器打开：

```
http://127.0.0.1:6080/vnc.html?autoconnect=1&resize=scale
```

> ⚠️ `6080` **只监听 `127.0.0.1`**（该桌面没有密码，避免同网段任何人都能操作桌面），
> 所以必须在**你自己的电脑**上先建一条 SSH 隧道 —— 详见 3.3。

**原理**（已改为 Xvfb 方案，原因见下）：

1. `Xvfb :100` 起一个虚拟 X11 显示
2. 桌面端跑在这个真实 X11 显示上 —— **渲染走标准 X11 路径，颜色正确**
3. `xpra shadow :100 --bind-rfb=127.0.0.1:5900` 把该显示以 RFB(VNC) 协议输出
4. `websockify` 把 noVNC 网页（`127.0.0.1:6080`）与 VNC 端口桥接

> ⚠️ **为什么不用 Qt 自带的 `vnc` 平台插件**（原来的做法）：
> `QT_QPA_PLATFORM=vnc` 的渲染会**把红蓝通道对调**（绿色不变）。
> 用纯红/绿/蓝三色块实测：
>
> | 位置 | Qt 正常渲染 | `QT_QPA_PLATFORM=vnc` |
> |---|---|---|
> | 左（红） | 红 ✅ | **蓝 ❌** |
> | 中（绿） | 绿 ✅ | 绿 ✅ |
> | 右（蓝） | 蓝 ✅ | **红 ❌** |
>
> 后果就是**视频里橙红色的火焰显示成蓝色**。改用 Xvfb 后实测：
> 三色块全部正确；用 `data/偏高.mp4` 实测视频区 `R=114 > B=90`（偏红/橙）✅。

- 换端口：`VNC_PORT=5901 WEB_PORT=6081 bash 启动远程桌面.sh`
- 换分辨率：`SCREEN=1600x900 bash 启动远程桌面.sh`
- 换显示号：`DISPLAY_NUM=101 bash 启动远程桌面.sh`
- 停止：终端里 `Ctrl+C`（或 `bash 停止服务.sh`，它会一并停掉 Xvfb / xpra / websockify 并清理 X 锁文件）
- 日志：`/tmp/mars_app.log`（桌面端）、`/tmp/mars_xpra.log`、`/tmp/mars_xvfb.log`
- ⚠️ 该桌面**没有密码**，请勿把 `6080` 暴露到公网。

**启动脚本会自动做预检**：如果上一次没退干净（终端被关掉、SSH 断开等），
脚本会先结束残留的 `Xvfb :100` / `ui_fireeye.py` / `xpra shadow` / `websockify`，
再删掉 `/tmp/.X100-lock`，然后才启动，所以可以反复执行，不会报
`(EE) Server is already active for display 100`。

> ⚠️ **已知问题：xpra 6.2.2 的 RFB 服务端点击失效（已打本地补丁）**
>
> 现象：浏览器里能看到桌面，但**鼠标点击没反应**（按钮点不动、选不了视频），
> `/tmp/mars_xpra.log` 里满屏：

> ```
>

> `button_action(device_id, wid, pointer, button, pressed, props)`（6 个参数），

>
> 补丁（已应用，若重装 / 升级 xpra 后点击又失效，重新打一次即可）：
>
> 文件 `~/.conda/envs/gui/lib/python3.12/site-packages/xpra/server/rfb/server.py` 第 164 行
>
> ```python
> # 改前
> self.button_action(device_id, 0, (x, y), 1 + button, pressed)
> # 改后（补上 props）
> self.button_action(device_id, 0, (x, y), 1 + button, pressed, {})
> ```
>
> 改完 `bash 停止服务.sh` 再 `bash 启动远程桌面.sh` 生效。
> 实测：点击「📂 本地视频」能弹出文件框、`Esc` 能关掉、加载 `data/偏高.mp4` 后画面持续变化，
> xpra 日志中 `TypeError` 计数为 0。

> ⚠️ **已知问题：网页里看不到鼠标指针（已打本地补丁）**
>
> 现象：noVNC 页面（`vnc.html`）里鼠标箭头**完全不显示**，只能盲点。
>
> 原因链：noVNC 会在 SetEncodings 里请求 **Cursor 伪编码 `-239`**，
> 但 `xpra/server/rfb/server.py` 里**没有任何发送光标形状的代码**
> （xpra 的光标支持在 `server/source/windows.py`，那是 xpra 自家协议用的，RFB 模块没接）。
> 于是 noVNC 拿不到光标图像，内部 `_cursorImage` 一直是空白的 `RFB.cursors.none`，
> `Cursor.clear()` 把 canvas 设成 `cursor:'none'` —— **远端没画光标、本地光标又被隐藏**，
> 结果就是指针彻底消失。
>
> 实测（`/tmp/probe_cursor.py` 直接对 5900 请求 `-239`）：
> 收到 `Raw×162` 个矩形更新，**光标形状更新 0 次**。
>
> 补丁（已应用；重装 / 升级 noVNC 后需重打）：
>
> 文件 `~/.local/share/novnc/core/util/cursor.js` 的 `clear()`
>
> ```javascript
> // 改前（没有远端光标时把本地光标也藏了）
> this._target.style.cursor = 'none';
> // 改后（回落到浏览器本地箭头；远端若发来光标，change() 仍会覆盖）
> this._target.style.cursor = 'default';
> ```
>
> 这是纯静态文件，**改完刷新浏览器页面即可**（JS 有缓存，用 `Ctrl+Shift+R` 强制刷新）。
> A/B 实测（用最小 DOM 桩直接跑 noVNC 的 `Cursor` 类）：
>
> | 场景 | 改前 | 改后 |
> |---|---|---|
> | 连接建立时 | `none`（不可见） | `default`（本地箭头）✅ |
> | 服务端不发光标 | `none`（不可见） | `default`（本地箭头）✅ |
> | 服务端发来真实光标 | `url(...)` | `url(...)`（行为不变）✅ |
>
> 若不想改代码，也可以在页面里点右上角齿轮 → 勾选 **Show dot when no cursor**，
> 用一个 3×3 的小点代替（不如本地箭头好用）。

### 3.3 在本地电脑上建隧道（访问远程界面）

远程桌面端口只监听远程主机的 `127.0.0.1`，**SSH 转发必须由你自己的电脑发起**

```

**方式 B：Windows 一键脚本（`Code/local_tunnel.bat`）**

把 `local_tunnel.bat` 和 `local_tunnel.ps1` 放到本地同一个文件夹，双击 `local_tunnel.bat`：

> 设置 → 应用 → 可选功能 → 添加功能 → **OpenSSH 客户端**。

   代价是并发分析会串行争用同一张卡，多人同时用时建议排队或改用队列。
